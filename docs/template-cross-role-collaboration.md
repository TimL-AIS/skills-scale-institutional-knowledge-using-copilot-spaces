# Cross-Role Collaboration Guide

## Purpose
Clarify how roles collaborate and hand off work across project phases to ensure accountability, minimize confusion, and maintain smooth workflow.

---

## Collaboration Principles

1. **Clear Handoffs:** Explicitly communicate when work moves from one role to another
2. **Shared Accountability:** Multiple roles may contribute to a deliverable; primary owner should be clear
3. **Proactive Communication:** Notify affected roles early about dependencies or blockers
4. **Documentation:** Document decisions and handoffs in project tracking systems
5. **Feedback Loops:** Establish regular touchpoints for cross-role alignment

---

## Phase-by-Phase Collaboration Matrix

### Initiation Phase

#### Primary Activities and Role Responsibilities

**Defining Business Case**
- **Lead:** Product Manager
- **Contribute:** Product Owner (user perspective), UX Designer (user needs)
- **Review:** Project Manager, Stakeholders
- **Handoff:** Approved project one-pager → Product Owner and Project Manager

**Success Metrics Definition**
- **Lead:** Product Manager
- **Contribute:** Product Owner (acceptance criteria), Quality Champion (quality metrics)
- **Review:** Stakeholders
- **Handoff:** Defined metrics → all team members for alignment

**Initial Risk Assessment**
- **Lead:** Project Manager
- **Contribute:** Quality Champion (quality risks), Change Manager (change risks), Technical Leads (technical risks)
- **Review:** Product Manager, Stakeholders
- **Handoff:** Risk register → Project Manager (ongoing owner)

**Team Formation**
- **Lead:** Project Manager
- **Contribute:** All role leads for resource needs
- **Support:** Change Manager (organizational alignment)
- **Handoff:** Team roster → All team members, onboarding begins

---

### Planning Phase

#### Primary Activities and Role Responsibilities

**Backlog Creation and Prioritization**
- **Lead:** Product Owner
- **Contribute:** Product Manager (strategic input), Developers (technical feasibility), UX Designer (design requirements)
- **Review:** Project Manager, Quality Champion
- **Handoff:** Prioritized backlog → Developers for estimation

**Sprint/Iteration Planning**
- **Facilitate:** Agile Coach
- **Lead:** Product Owner (what), Developers (how)
- **Contribute:** Quality Champion (test approach), UX Designer (design readiness)
- **Handoff:** Sprint commitment → all team members, sprint backlog finalized

**Test Strategy Development**
- **Lead:** Quality Champion
- **Contribute:** Developers (test approach), Product Owner (acceptance criteria)
- **Review:** Project Manager
- **Handoff:** Test plan → Developers and QA team for execution

**Design Specifications**
- **Lead:** UX Designer
- **Contribute:** Product Owner (requirements), Developers (feasibility feedback)
- **Review:** Product Manager
- **Handoff:** Design specs → Developers for implementation

**Change Management Planning**
- **Lead:** Change Manager
- **Contribute:** Project Manager (timeline), All roles (change impact)
- **Review:** Leadership, Stakeholders
- **Handoff:** Change plan → all team members, communication begins

---

### Execution Phase

#### Primary Activities and Role Responsibilities

**Feature Development**
- **Lead:** Developers
- **Contribute:** UX Designer (implementation guidance), Quality Champion (test support)
- **Review:** Developers (peer review)
- **Handoff:** Completed code → Quality Champion for validation

**Quality Validation**
- **Lead:** Quality Champion
- **Contribute:** Developers (bug fixes), Product Owner (acceptance criteria clarification)
- **Review:** Product Owner
- **Handoff:** Validated features → Product Owner for acceptance

**Product Owner Acceptance**
- **Lead:** Product Owner
- **Contribute:** UX Designer (UX validation), Quality Champion (quality verification)
- **Review:** Product Manager (as needed)
- **Handoff:** Accepted work → Done column, ready for release

**Impediment Resolution**
- **Lead:** Agile Coach
- **Contribute:** Project Manager (escalation), relevant stakeholders
- **Support:** Change Manager (if process changes needed)
- **Handoff:** Resolved impediment → team for continued work

**Progress Tracking**
- **Lead:** Project Manager
- **Contribute:** All roles (status updates)
- **Facilitate:** Agile Coach (standups)
- **Handoff:** Status reports → Stakeholders, Product Manager

**Design Validation**
- **Lead:** UX Designer
- **Contribute:** Product Owner (requirements check), Developers (technical constraints)
- **Review:** Quality Champion (usability testing)
- **Handoff:** Approved design → Developers confirmed ready

---

### Release Phase

#### Primary Activities and Role Responsibilities

**Release Readiness Assessment**
- **Lead:** Project Manager
- **Contribute:** Quality Champion (quality sign-off), Product Owner (acceptance sign-off), Developers (technical readiness)
- **Review:** Product Manager
- **Handoff:** Go/No-go decision → all team members

**Quality Sign-off**
- **Lead:** Quality Champion
- **Contribute:** Developers (verification), Product Owner (acceptance validation)
- **Review:** Project Manager
- **Handoff:** Quality approval → Project Manager for release decision

**Release Communication**
- **Lead:** Change Manager
- **Contribute:** Product Manager (value messaging), Product Owner (feature details)
- **Review:** Project Manager
- **Handoff:** Communication materials → stakeholders and users

**Deployment Coordination**
- **Lead:** Developers (technical deployment)
- **Coordinate:** Project Manager (timeline), Change Manager (communication)
- **Monitor:** Quality Champion (post-deployment validation)
- **Handoff:** Deployed release → Operations/Support teams

**User Experience Validation**
- **Lead:** UX Designer
- **Contribute:** Product Owner (user feedback), Quality Champion (usability issues)
- **Review:** Product Manager
- **Handoff:** UX validation → Product Manager for success measurement

---

### Retrospective Phase

#### Primary Activities and Role Responsibilities

**Retrospective Facilitation**
- **Facilitate:** Agile Coach
- **Participate:** All team members
- **Document:** Project Manager
- **Handoff:** Action items → responsible owners, tracked in backlog

**Process Improvement**
- **Lead:** Agile Coach
- **Contribute:** All roles (feedback), Change Manager (implementation planning)
- **Review:** Project Manager
- **Handoff:** Approved improvements → Change Manager for rollout

**Lessons Learned Documentation**
- **Lead:** Project Manager
- **Contribute:** All roles
- **Review:** Product Manager, Agile Coach
- **Handoff:** Documented lessons → knowledge base, future project teams

**Metrics Review**
- **Lead:** Product Manager
- **Contribute:** Quality Champion (quality metrics), Project Manager (delivery metrics)
- **Review:** Stakeholders
- **Handoff:** Insights → Product Owner for backlog adjustments

## Role-Specific Handoff Checklists

### Product Owner → Developers
**When:** Handing off user stories for implementation
- [ ] User story has clear acceptance criteria
- [ ] Dependencies are identified and documented
- [ ] Design specifications are attached (if applicable)
- [ ] Priority is clearly marked
- [ ] Available for questions during development

### Developers → Quality Champion
**When:** Handing off completed work for testing
- [ ] Code is reviewed and approved
- [ ] Unit tests are passing
- [ ] Test cases are identified or created
- [ ] Known limitations are documented
- [ ] Deployment/test environment is ready

### Quality Champion → Product Owner
**When:** Handing off tested work for acceptance
- [ ] All test cases executed and passing
- [ ] Defects are documented and resolved (or accepted)
- [ ] Test evidence is available
- [ ] Quality metrics meet standards
- [ ] Ready for product owner review

### Product Owner → Product Manager
**When:** Handing off released features for measurement
- [ ] Features are deployed and validated
- [ ] Success metrics are being tracked
- [ ] User feedback mechanism is in place
- [ ] Known issues are documented
- [ ] Ready for impact assessment

### UX Designer → Developers
**When:** Handing off designs for implementation
- [ ] Designs are finalized and approved
- [ ] Design specs and assets are provided
- [ ] Accessibility requirements are documented
- [ ] Responsive behavior is specified
- [ ] Available for implementation questions

### Project Manager → Change Manager
**When:** Handing off change requirements
- [ ] Change impact is assessed
- [ ] Timeline for change is defined
- [ ] Affected stakeholders are identified
- [ ] Communication needs are outlined
- [ ] Training or documentation needs are specified

### Agile Coach → Team
**When:** Handing off process improvements
- [ ] Improvement is clearly defined
- [ ] Benefits and rationale are explained
- [ ] Implementation approach is agreed upon
- [ ] Success criteria are established
- [ ] Support and coaching are available

### Handoff Meeting Agenda

**Duration:** 30 minutes

1. **Context (5 min):** What has been completed and why
2. **Walkthrough (15 min):** Detailed review of deliverable
3. **Q&A (5 min):** Questions and clarifications
4. **Next Steps (5 min):** Confirm actions, timeline, and follow-up

---

## Escalation Guidelines

When handoffs encounter issues, follow this escalation path:

**Level 1 - Direct Communication (0-24 hours)**
- Resolve between the two roles directly
- Use team communication channels
- Document resolution

**Level 2 - Project Manager (24-48 hours)**
- Involve Project Manager if unresolved
- PM facilitates resolution or escalates
- Update risk register if needed

**Level 3 - Agile Coach or Leadership (48+ hours)**
- Agile Coach for process issues
- Product Manager for scope/priority issues
- Leadership for resource or organizational issues

## Accountability Matrix (RACI)

Use this matrix to clarify accountability for key activities:

- **R** = Responsible (does the work)
- **A** = Accountable (ultimate ownership, single point)
- **C** = Consulted (input before decision)
- **I** = Informed (notified after decision)

| Activity | PM | PdM | PO | Dev | QC | CM | AC | UX |
|----------|----|----|----|----|----|----|----|----|
| Define product vision | C | A | R | I | I | I | I | C |
| Prioritize backlog | I | C | A/R | C | I | I | I | C |
| Sprint planning | C | I | R | R | C | I | A | C |
| Feature development | I | I | C | A/R | C | I | I | C |
| Quality testing | C | I | C | C | A/R | I | I | I |
| Acceptance review | I | I | A/R | I | C | I | I | C |
| Release coordination | A/R | C | C | R | C | R | I | I |
| Retrospective | R | I | C | C | C | I | A | C |
| Process improvement | C | I | I | C | C | C | A/R | I |

**Legend:**
- PM = Project Manager
- PdM = Product Manager  
- PO = Product Owner
- Dev = Developers
- QC = Quality Champion
- CM = Change Manager
- AC = Agile Coach
- UX = UX Designer
